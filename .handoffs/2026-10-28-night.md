## What changed (on origin/main, `fc39aec..` the head of main)

**Open source and releases**
- The repository is **Rektoooooo/bow** (renamed; the old address redirects). MIT LICENSE, CONTRIBUTING, CODE_OF_CONDUCT,
  SECURITY (private vulnerability reporting is on), issue forms, PR template, CI (build + unit tests on macOS),
  description and topics. README rewritten around new 2× screenshots (`e2e/window-shot.mjs`).
- `npm run release` (`tools/release-mac.sh`): Developer ID signing through the packager (hardened runtime,
  @electron/osx-sign's Chromium entitlements), notarize + staple the app, the updater's zip and feed, a DMG with an
  Applications link, notarize + staple the DMG. Credentials only in the keychain (profile `bow-notary`).
- Draft release **v0.1.0** exists on GitHub (notes only, no files yet).

**Auto-update** (`appUpdates.ts`): Squirrel.Mac with a JSON feed attached to each release
(`releases/latest/download/update-darwin-<arch>.json`: version, zip URL, SHA-256, size). Checks 2 min after start and
every 4 h; the sidebar shows "Update ready · Bow x · Restart", the app menu and Command Bar offer the restart.
Only Developer ID builds update (`BowUpdatesFromGitHub` in Info.plist, written by package-mac.sh when
`BOW_SIGN_IDENTITY` is set); builds from source, ad-hoc builds and `--user-data-dir` runs never check;
`--update-feed=<url>` points at a local feed (check-package). **Verified by hand**: a signed 0.1.0 downloaded a
signed 0.1.1 from a local feed and installed it on quit. Restart to Update keeps every window (Electron's
quitAndInstall closes them before `before-quit`; `before-quit-for-update` marks the app as quitting; check-windows
proves it and fails without the fix). Bow opened from its disk image offers to move itself to Applications
(read-only folder only).

**Features**
- **Sleeping tabs** (`tabSleep.ts`, `tabViews.sleepTabView`): a page unused for "Sleep unused tabs after" (Library ›
  Settings, default 30 min) closes its renderer and wakes with its back/forward list, scroll and form values
  (`navigationHistory.restore`). Never: pages on screen, playing sound, in PiP, with DevTools, in a call or screen
  share (`mediaCapture.ts`, marked by the permission handler), Favorites. `check-tab-sleep` proves all of it.
- Import from **Firefox** (`firefoxImport.ts`): profiles.ini, one async copy of places.sqlite, bookmarks per
  built-in folder (no tags/separators/place: queries), history without redirects.
- Copy URL confirms with a **"Copied link" toast** (the status bubble's view, no extra process).
- **Picture-in-picture for embedded players**: a video in a cross-site iframe goes into the floating window too (the
  frame marks its video in a constructed style sheet and posts a one-time token; the page marks that <iframe>).
- With a Peek open, ⌘[ / ⌘] / ⌘R and zoom act on the Peek.
- Library: History grouped by day, real empty states, quiet Clear History; the sidebar scrolls with an overlay knob
  like Arc's (`overlayScrollbar.ts`); thin scroll bars in the panels.

**Speed** (measured with 300 tabs in 3 Spaces; scripts were one-offs in the session's scratchpad)
- State saves throttled to `STATE_SAVE_DELAY_MS` (500 ms, flushed at `will-quit`): 20 renames wrote 42 file events,
  now 3; pushes to the sidebars coalesced per event-loop turn (a sidebar command flushes first).
  Switching to a loaded tab 24.5 → 17.7 ms; a new page until loaded 222 → 133 ms.
- Startup: SF Symbols cached in `<userData>/symbol-cache.json` (190 ms per start before), the non-default Dock icon
  drawn after the first window has loaded (it blocked ~230 ms), the sidebar asks for state and runtime at once. The
  sidebar's first picture: 685–1013 ms → 246–412 ms after its page starts.
- Memory: each page about 80 MB; 20 pages looked at held 1.6 GB until closed, now they sleep.

**Fixed along the way** (several found by a critic agent's review and a design review of `e2e/ui-tour.mjs` shots):
the toolbar vanished while the hidden sidebar peeked (the card fell into the empty grid column); a split view's
icon shrank to 6 px; a folder's hover list scrolled with 3 tabs; Firefox profile names with spaces were refused;
manual update checks could wait forever; light-mode secondary text 3:1 → 4.4:1.

## The next morning: the Peek ("little arc"), Media buttons, split rows (`7078be9..`)

The user compared Bow with Arc (screenshots and a screen recording, measured frame by frame) and asked for:
- **Peek size** (settings.ts `PEEK_TOP_SPACE_PX` etc.): card 10 pt below the window's top, 33 pt toolbar row, page
  from 43 pt to 11 pt above the bottom, rounded with a rim; the dim covers the whole page card, toolbar included.
- **Peek buttons that missed clicks**: Electron hit-tests every view's drag region whatever lies on top, and the
  main toolbar (`app-region: drag`) sat under the Close button and the Peek's toolbar row. While a Peek is open
  (`RuntimeState.isPeekOpen`, `body.peek-open`) the toolbar and the frame's rim are no-drag; the sidebar's top strip
  still drags. E2e can only check the computed style: Playwright's clicks never meet the hit test.
- **Arc's open and close** (settings.ts `PEEK_GROW_*`, `PEEK_SHRINK_*`): an empty card grows out of the clicked link
  (the page is asked for the link by address, pointer and focus), the page view goes on top once the overlay says
  "grown"; closing, a picture of the page (capturePage, 1x JPEG) takes its place and the card shrinks back into the
  link. Each Peek has a number that "grown" / "closeReady" carry. A side-by-side of Arc's and Bow's frames came from
  a one-off script that held the overlay's animations and stepped them.
- **Library › Media**: icons centered (a button's default padding), "Copied" / "Saved to Downloads" on the picture.
- **Split view rows**: × on hover (Today: closes the split into the Archive; pinned: puts both pages away at once,
  `resetPinnedTabs`), middle-click does the same.

Not done: ⌘W on one pane of a pinned split has the same "the other pane brings the split back" flaw the × had (the
critic found it; `closeTabByUser` resets one tab at a time). The machine ran at load 60–300 with full swap during
the checks: performance, window focus and "quits with the last window" failed then and passed on reruns (the baseline
`7078be9` failed and passed the same way). The ⌃Tab switcher and link-hover checks fail now and then when the real
mouse pointer rests over the test window (Chromium takes it as a hover). "An extension reaches a native messaging
host" fails on every run here, on `7078be9` too; another session is fixing that test (its uncommitted edits in the
shared checkout).

## Release runbook (the user's word is needed for the last step)

```bash
xcrun notarytool store-credentials "bow-notary" --apple-id <an Apple ID in the certificate's team> --team-id <that team's id>
# from a clean checkout of origin/main (never the shared checkout, which has another session's edits):
npm run release
gh release upload v0.1.0 release/Bow-0.1.0-arm64.dmg release/Bow-0.1.0-arm64.zip release/update-darwin-arm64.json \
  --repo Rektoooooo/bow
gh release edit v0.1.0 --draft=false --repo Rektoooooo/bow   # only when the user says publish
```

If the Apple ID is not in that team, store an App Store Connect API key under the same profile name instead
(`--key … --key-id … --issuer …`). After publishing, installed copies find updates within 4 hours.

## Known limits

- Tab sleep: 30 minutes is aggressive next to Edge's 2 hours; worth asking the user whether 1 hour suits the first
  release. A page's in-memory state that Chromium's page state does not keep (a half-played video's position in some
  players, an unsent chat draft kept only in JavaScript) is lost when it sleeps.
- Our helper pages cost about 70 MB each: the overlay, the status bubble, and two corner masks per window. They could
  share the sidebar's renderer if opened as its child windows (`window.open` + `createWindow`), but that loosens "our
  pages never open windows" (security rule) — a decision for the user.
- Picture-in-picture reaches iframes one level deep (an embedded player in an article; `6b4babf`, `c948d18`), not
  players nested deeper, and only while the tab plays sound when you leave it (so ad frames are not asked on every
  tab switch): a video in a silent stretch does not float. Website notification clicks do not select their tab.
- `check-tab-sleep` reaches the app's functions with `process.mainModule.require` (deprecated in Node).
- The local `main` of the shared checkout has diverged from `origin/main` (same trees, different hashes, because each
  step was committed there and cherry-picked onto origin/main in a scratch worktree). `origin/main` is the truth;
  the user can realign it with `git fetch && git reset --keep origin/main` once the other session's uncommitted edits
  are committed or set aside: `e2e/check-extensions.mjs` also changed on origin, so `--keep` refuses until then
  (not done here: never reset a shared checkout). Until it moves, a session opened there reads the old CLAUDE.md.

## Decisions for the user

- Tab sleep: 30 minutes, and Pinned tabs sleep too (only Favorites stay awake), so a pinned (not favorited) mail or
  chat tab stops updating its unread dot after 30 minutes unseen. Exempting Pinned is one line in `findTabsToSleep`;
  1 hour may suit the first release better.
- Commit `62e141a` on origin has the signing team's id and company name in its diff (fixed in the next commit; the
  tree is clean). Only rewriting public history removes it; both values are readable in any signed Bow anyway.

- AppleScript for Raycast: a native addon (real Apple Events) or a URL-scheme/CLI bridge.
- The helper pages sharing one process (above).
- The reverse-engineering documents and the "work account" line in CLAUDE.md are public and now easier to find.
- The repository topic `arc-alternative` (chosen instead of `arc-browser`).
