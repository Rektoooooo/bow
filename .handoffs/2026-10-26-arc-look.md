## How the look is measured (keep doing it this way)

- The reference screenshots are **1 px per point**; the Arc window sits at (56, 38) in each image, 1888 × 1032 pt.
  `node e2e/arc-compare.mjs` renders our window at that size with a made-up sidebar of the same shape and writes
  side-by-side crops (Arc left, ours right) plus `layout.json` (our element boxes) to `e2e/output/arc-compare/`.
  Pixel scans with Python/PIL on `reference/arc-ui/*.webp` give exact edges; never estimate by eye.
- Measured values live as named constants with their source: `src/shared/settings.ts` (sidebar 242, card gap 7,
  inset 10, toolbar 32, developer toolbar 38), the top of `src/renderer/sidebar.css` and the Command Bar / Control
  Center blocks in `src/overlay/overlay.css`.
- **Colors:** Chromium blends rgba overlays in the display's color space, so alphas are calibrated against Arc's
  pixels (the dark tokens in `sidebar.css` say which pixel each matches). Text uses AppKit-like smoothing
  (`-webkit-font-smoothing: auto`).
- **Frame palette** (`src/shared/themePalette.ts`): dark = color × 0.37·intensity lifted 19.2 % toward white
  (black → #313131); light shows dark colors as #e6e6e6. Spaces without an Arc theme are neutral black.
- **Toolbar tint** (`src/main/toolbarTint.ts`, `sidebar.ts applyToolbarTint`): the page's top row, cached per site
  like Arc's TopBarColorCache; near-black tops show #424242 (GitHub in shots 3/4; one sample each side).

## Decisions worth knowing

- **Card clipping:** Electron cannot give the page square top corners under a toolbar, so the toolbar is drawn by
  the sidebar page and tinted like the page; the page view keeps a uniform 10 pt radius.
- **Native motion:** `View.setBounds(…, { animate })` reports the end place at once and could not be verified
  without screen recording, so `tabViews.ts` glides the page view itself (cubic ease-out, 260 ms, 8 ms steps) and
  `sidebar.css` moves the card on the same curve (`--motion-layout`). `check-motion.mjs` samples the positions.
- **Overlay closing** waits 120 ms for the fade before the view leaves (`src/main/overlay.ts`); e2e checks that ask
  for a new prompt right after closing must wait for it (`permission-check.mjs` does).
- **Developer Mode** is per site (`src/shared/developerMode.ts`, `BrowserState.developerModeSites`), on by default
  for localhost/127.0.0.1/*.localhost/*.test. The developer tools panels open through `DevToolsAPI.showPanel` /
  `enterInspectElementMode` (the DevTools embedder API). The button glyph mapping (capture, network) is ours.
- `getSiteKey` moved to `src/shared/siteKey.ts` (re-exported by `src/main/urls.ts`) so the sidebar can use it.
